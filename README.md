# SecureMailScope

Evidence-based review of **email transport security** (SMTP / IMAP / POP3 with STARTTLS/STLS, and the TLS beneath them) in
packet captures you are authorised to analyse. TShark dissects the traffic; deterministic rules produce findings; every
finding links back to packet-level evidence. Optional AI only *explains* findings the rules already established.

> Demo data is synthetic: **CONTROLLED SYNTHETIC DEMONSTRATION DATA — NOT REAL CUSTOMER TRAFFIC.**

## Requirements
- Python 3.11+ (developed on 3.14), Node 18+ / npm
- **TShark (Wireshark CLI) 4.x** on `PATH` — the app starts without it but shows a clear banner and refuses analysis.
  Developed against TShark 4.7.4.

## Quick start
```bash
./run_dev.sh            # creates backend/.venv, installs deps, starts both servers
```
Manual:
```bash
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --port 8000          # API  http://localhost:8000  (Swagger: /docs)
cd ../frontend && npm install && npm run dev         # UI   http://localhost:5173  (proxies /api)
```
If port 8000 is busy: `API_PORT=8010 ./run_dev.sh` (or `SMS_API_URL=http://localhost:8010 npm run dev`).

## Demo (2 minutes)
1. Open http://localhost:5173 → **Overview** → *Load demo dataset* (four synthetic captures are analysed).
2. **Security Findings** → open a finding → *Open packet evidence* (Finding → Evidence → raw bytes → session).
3. **Protocol Explorer / TLS Inspector / Certificate Inspector** for `smtp_deprecated_tls10.pcap`.
4. **Reports** → generate PDF/HTML/JSON/CSV. **Rules** → toggle a rule and re-run an analysis.
5. Or upload your own authorised PCAP under **New Analysis**.

## Known limitations (honest list)
- No TLS decryption; TLS 1.3 certificates are encrypted and reported as *unavailable*, not as a defect.
- Certificate checks are local metadata checks only: **no trust-chain, revocation or hostname validation** claims (SMS-CRT-008 is an SNI/SAN match only).
- Only SMTP, IMAP and POP3 are parsed. Other protocols are ignored. Link types supported: Null, Ethernet, Raw, Linux SLL/SLL2.
- TShark `-T json` is loaded in memory per analysis; very large captures (limit 50 MB / 2M packets by default) can be slow or memory-hungry.
- Decode-as for non-standard ports relies on banners/commands; ports shared with other services can be misdetected.
- Validated only on **synthetic** fixtures generated in this repo; accuracy on real-world captures is not claimed.
- The original proof-of-concept source files were not available, so the dissection engine was rebuilt from the specification.
- Frontend automated tests cover utilities and core UI components (10 tests) — not every page; pages were exercised manually in a browser.
- Single-user, local-only app: no authentication. Do not expose it to a network.
